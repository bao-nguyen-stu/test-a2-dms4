Ăn't — Specification, Privacy, Data Model & Themes

Visual Wireframes & Interaction Principles

4 Mobile Wireframes + 1 Responsive Desktop View

  • Mobile-first, private by default, and quick to use around a table.
  • One clear task per screen, with large tap targets and readable option cards.
  • Show round progress without revealing who voted for what.
  • Use calm, neutral language; results show counts and ranking, not individual choices.
  • Provide a privacy screen for Pass-and-Play and a clear “all votes submitted” state online.
  • On tablets and desktops, use a wider shared view for setup and results while keeping voting private on each phone.
Journey & Decision Logic

6-Step Flow & Interaction Direction

  1. Choose Pass-and-Play or Online Room; set group size.
  2. Set location and context. If location is declined, choose a campus/district preset or enter suggestions manually.
  3. Review nearby options, add/remove candidates, and confirm the final set.
  4. Each person privately marks any number of options they would rather avoid, reviews, then submits. No interim tally appears.
  5. After all submissions, sort by ascending veto count. A tie remains visibly tied; the group may accept it or run one anonymous preference round among finalists.
  6. The result says “least vetoed,” not “everyone agrees.” If every option receives vetoes, show “no clear fit” and offer a new round or revised constraints. If an online room stalls, cancel or close it with an incomplete-status notice; never present partial results as a completed group decision.
Technical Plan, AI & Privacy

Architecture & Privacy Guardrails

  • Front end: React + Vite, responsive components; public web hosting; GitHub for source, issues and release history.
  • Location/data: Optional browser geolocation; versioned local JSON with coordinates, source/check date, dish and known-amenity tags; Haversine distance; campus/district fallback.
  • Online mode: A small backend such as Supabase stores temporary sessions, candidates and submitted ballots. Use random session/participant tokens, restrictive access and server-side aggregation; clients must not read individual ballots.
  • AI beyond a wrapper: Parse “raining, low budget, need AC near campus” into a reviewable filter schema. AI must not invent venue facts. Week 8 uses a deterministic keyword/tag parser; AI integration is a stretch after the core flow works.
  • Privacy: Location stays on-device for local ranking. Online ballots are hidden from other participants, not necessarily from infrastructure. Minimize logs, explain privacy, expire session data, and never send coordinates or ballot content to AI. Preserve local mode if realtime/AI fails.

Appendix C · Evidence Log, Data Model & Risk Register

Phụ lục C · Nhật ký bằng chứng và rủi ro kỹ thuật

  • Evidence log protocol: After each interview or test, record participant code, method/mode, group context, observed behavior, direct quote with consent, design implication and open question. Separate observation from interpretation.
  • Venue record: id, name, coordinates, source/check date, dish tags, amenity tags with known/unknown status, map query.
  • Session: random id, mode, candidate ids, expected participant count, status and expiry.
  • Ballot: session id, random participant token, vetoed candidate ids, submitted time; no name, email or account.
  • Aggregate: candidate id, veto count, completion count and tie state; returned only after the round closes.
  • Local vs Online storage: Local mode session stays on device. Online mode needs temporary server storage; disclose this before joining and expire data after completion.
  • Key risks & responses: Shared-device privacy weaker than expected → clear each turn, neutral hand-off, no early tally, state physical privacy limit. GPS denial or stale venue data → presets/manual suggestions, source/check date, unknown tags and map-search fallback. Online room stalls/guessed → short-lived codes, size limits, server validation, no ballot reads, cancel/incomplete state. AI misreads context/invents amenities → rules-first, strict filter schema, user review; AI never writes venue facts. Scope slips → freeze MVP after Week 6; complete both voting modes before AI/live Places.
